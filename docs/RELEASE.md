# 发布、验收与回滚

本项目同时使用 GitHub 保存可审查源码、OpenAI Sites 保存和部署正式站点、社团工作台记录治理与验收。三者的状态需要显式对应，不能根据其中一个成功推断另外两个成功。

## 1. 合并门槛

1. 从最新 `main` 创建功能分支，修改范围与规范或任务一致。
2. 本地运行 `npm ci` 和 `npm run verify`。
3. 提交 Pull Request，说明用户可见变化、隐私/数据影响、测试证据和未测范围。
4. GitHub Actions 的 `verify` 作业通过后进行人类审查。
5. 涉及评分规则、隐私、网络请求、存储迁移、Service Worker 或环境变量的变化必须有相应测试和回滚说明。
6. 由有权限的人在 GitHub 合并；工作台和 AI 不执行自动合并。

## 2. Sites 发布

1. 记录准备发布的 `main` 提交 SHA，确认工作区干净。
2. 保留 `.openai/hosting.json` 中既有 `project_id`，读取 Sites 当前访问范围；普通发布不得修改访问范围。
3. 将该提交同步到 Sites 源仓库，执行生产构建并从同一提交生成发布归档。
4. 保存新的 Sites 版本并部署到现有项目，不创建重复站点。
5. 等待部署进入成功状态，记录 Sites 版本号、部署 URL、提交 SHA 和时间。
6. 若源代码同步、保存版本、构建或部署任一步失败，不把该版本记为已发布。

当前 Sites 项目使用 Vinext 与 Cloudflare Worker 运行环境。`NEXT_PUBLIC_SITE_URL` 应指向实际公开地址。公开资料研究仅在有明确产品决定时设置：

```dotenv
ENABLE_PUBLIC_RESEARCH=true
ANTHROPIC_API_KEY=...
```

密钥只放在 Sites 环境变量中。BYOK 深度反馈使用访问者自己提供的凭据，不需要把访问者凭据配置到部署环境。

## 3. 发布后冒烟检查

- 首页可加载，静态图标、OG 图片与 PWA manifest 正常。
- 预设题可以进入准备、演说、反馈和重讲流程。
- 不授予麦克风或不提供录音时，手动讲稿路径仍可继续，不伪造声音指标。
- 本地评分能完成；历史可保存、查看、导出和删除。
- 未启用公开资料研究时显示明确不可用状态，而不是无限加载或空白。
- 若本次声明验证了录音、Whisper、WebGPU/WASM、PWA 安装或真实 AI 服务商，应记录浏览器、设备和结果；否则标为未测。
- 检查浏览器控制台和 Sites Worker 日志没有新增的高频错误或秘密泄露。

## 4. 工作台记录

工作台项目 ID 为 `96b9e0fc-de3d-41e7-b47e-3a1f3f84fec8`。每次正式发布至少记录：规范版本与摘要、GitHub 仓库和提交、关联 PR、Sites 版本与 URL、自动检查、人工冒烟结果、验收人、已知问题和回滚点。

首次接入时先上传由 `README.md`、`AGENTS.md`、`.workbench/project.json`、`docs/PROJECT_SPEC.md` 和本文件组成的规范草稿，再走人类审阅、立项与正式规范发布流程。仓库绑定、组织建仓许可和规范批准分别确认。

## 5. 回滚

1. 立即停止继续发布并保存失败证据。
2. 在 Sites 重新部署最近一个已验证版本，确认核心页面恢复。
3. 若问题来自代码，在 GitHub 使用新的回退提交或修复 PR；不改写已经共享的提交历史。
4. 重新执行 `npm run verify`、Sites 部署和冒烟检查。
5. 在工作台记录事故影响、恢复版本、最终修复提交与未解决风险。

站点版本回滚不会自动恢复浏览器本地数据。涉及存储格式或 Service Worker 的变化必须在发布前验证向后兼容和缓存更新路径。
