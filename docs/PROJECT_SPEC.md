# 讲清楚项目规范草稿 · 0.1.0

> 本文整理现有代码与 README 中可核实的产品事实，并提出发布要求。所有需求状态仍待社团人类审阅；本文不代表立项、规范批准、成员认领或上线验收。

## 1. 目标与范围

讲清楚面向希望提升中文表达能力的个人使用者，把一次练习组织为限时准备、面向指定听众演说、获得可核对反馈、围绕同一题目重讲并比较变化的完整闭环。

首版范围包括题库与自定义题、录音与回听、本地转写、本地声音分析、六维本地量表、可选 BYOK 深度反馈、同题重讲对比、训练历史、趋势和 JSON 导出，以及 PWA 安装与离线外壳。公开资料研究是部署方显式启用的可选能力。

首版不承诺专业考试评分、事实核验、医学或人格判断、跨设备同步、多人协作、训练记录导入恢复，或在所有浏览器与设备上获得相同的 WebGPU、录音格式和性能表现。

## 2. 核心流程与交互

1. 用户选择内置题目、导入自定义题，或在功能启用时生成带来源的研究题。
2. 用户确认听众、任务和时间限制，阅读资料并准备提纲。
3. 用户允许麦克风后录制演说，可暂停、回听、重录；也可在无法录音或转写时提供手动讲稿。
4. 浏览器本地完成 Whisper 转写和声音分析。WebGPU 不可用时回退到 WASM；失败时提供明确恢复路径。
5. 系统使用可复现规则生成本地量表。只有在用户明确同意并选择服务商后，才把讲稿、题目资料和聚合声音指标发送给 AI 服务商获取深度反馈。
6. 用户围绕同一题目重讲，系统只比较两次均有可靠证据的维度。
7. 用户查看历史与趋势，可以导出或删除本机记录。

加载、权限拒绝、模型下载、转写失败、服务商失败、证据不一致、空历史和存储失败均应有文字说明，不只依赖颜色或图标。主要流程支持键盘操作、移动端布局和减少动画偏好。

## 3. 隐私、权限与安全边界

- 原始录音默认只在当前设备内存中处理；仅在用户开启保存选项后写入 IndexedDB，不能发送给 AI 服务商。
- 训练历史、题目快照与生成题保存在本机 `localStorage`；录音与文字记录分开存储。
- BYOK API Key 只在页面内存或当前标签页会话内使用，不进入训练历史、导出文件、日志或仓库。
- 深度反馈请求必须携带明确同意，且只发送完成任务所需的讲稿、题目资料和聚合声音指标。
- 同源转发只允许公网 HTTPS 地址，拒绝 IP、私网或保留地址、用户信息、非允许端口、重定向和未授权请求头；响应不得缓存。
- 第三方中转站能够看到用户提供的 Key 和获准发送的内容，界面必须提醒用户仅使用可信服务。
- 公开资料研究只在部署方设置 `ENABLE_PUBLIC_RESEARCH=true` 并提供服务端凭据时启用；未配置时返回清晰的不可用状态。

## 4. 数据与接口

浏览器端使用 `localStorage` 保存文字历史和题目，使用 IndexedDB 保存可选录音。记录需要保留评分版本、提示词版本、题目快照、创建时间和可比较维度，避免新算法静默改写旧结果。

服务端接口包括服务商连接测试、深度反馈、研究题和随机题生成。请求必须经过 Zod 结构校验、同源检查、长度限制、超时与标准化错误处理。AI 反馈中的讲稿引文、声音时间段、指标 ID 和资料来源必须能与输入证据核对；验证失败的结果不得作为完成反馈展示。

任何存储格式变化都需要迁移策略、向后兼容说明和测试。当前只有导出，没有导入恢复，必须继续作为已知限制展示。

## 5. 运行与部署约束

- Node.js `>=22.13.0`，依赖版本以 `package-lock.json` 为准。
- 使用 React、Next.js App Router、Vinext、Vite 和 Cloudflare Worker 运行环境。
- 正式地址通过 `NEXT_PUBLIC_SITE_URL` 提供给元数据；未设置时使用项目的 Sites 地址。
- `ANTHROPIC_API_KEY` 等服务端凭据只存放在托管环境变量中，不进入代码、规范包或提交历史。
- Sites 项目 ID 已保存在 `.openai/hosting.json`；普通发布必须保留现有项目身份和访问范围。
- GitHub 合并与 Sites 部署是独立事实，详细流程见 `docs/RELEASE.md`。

## 6. 测试与验收

每次合并前至少执行 `npm ci` 和 `npm run verify`。现有自动测试覆盖评分稳定性、声音分析边界、反馈证据校验、服务商配置 Schema 与转发层网络安全。正式版本还需要人工冒烟检查：页面可打开、预设题可进入训练、手动讲稿可完成本地评分、历史可写入与导出、可选功能关闭时提示正确、移动端主要步骤无阻塞。

录音、麦克风权限、真实 Whisper 模型下载、WebGPU/WASM 回退、PWA 安装、Service Worker 更新和真实 AI 服务商联调不能仅由单元测试替代。未实际执行的检查必须记录为未测。

## 7. 发布与回滚

功能改动从分支和 Pull Request 进入 `main`，GitHub Actions 必须通过代码检查、单元测试和生产构建。发布者再将同一提交同步到 Sites，保存版本并部署；部署完成后核对线上版本、提交和冒烟结果。故障时优先恢复上一已验证 Sites 版本，再通过 Git 回退修复主分支。不得通过扩大站点访问范围来绕过发布问题。

工作台中的规范批准、GitHub PR 合并、Sites 部署与真人验收分别记录。只有正式分支内容与获批规范摘要一致后，工作台才可更新正式规范指针。
